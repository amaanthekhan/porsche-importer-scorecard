1 · Where the region stands PUBLIC DATA

The only performance data that is genuinely public is regional. It sets the context a scorecard has to live in: growth since 2020, a record 911 share, and a sharp 2026 slowdown that the release links partly to the conflict in the Middle East.

New-vehicle deliveries, Middle East, Africa, Levant and India

reported by Porschederived from reported growth rates (approximate)

2019: Porsche's 2019 results release. 2024 and 2025: Porsche newsroom. 2020, 2022 and 2023 are back-calculated from "+55% since 2020", "+4% in 2024" and "+11% the year prior", so treat them as approximate. 2021 was not stated.

What the numbers say

  • +55% since 2020, roughly 9% a year compounded (implied 2020 base of about 6,200). 2025 was the region's best year in 12 years.
  • The 911 grew from 15% to 23% of regional sales between 2020 and 2025: mix is moving toward the high-performance end.
  • Growth is flattening: +11% (2023), +4% (2024), +1% (2025).
  • Network investment in 2025: four new Porsche Centres, three renovations, three Porsche Now locations.
  • Global 2025: 279,449 deliveries worldwide, down 10%.
  • H1 2026: the "Overseas and Emerging Markets" sales region fell 18% (30,158 to 24,877) against 16% worldwide; Porsche names the Middle East conflict and the end of 718 combustion production as contributing factors and does not quantify either. That sales region is broader than the Middle East and Africa office's territory, so it is a context signal, not the same population.
Why this matters for a scorecard: when volume is under pressure for reasons outside an importer's control, a volume-only ranking punishes the wrong thing. That is the argument for scoring quality and loyalty pillars alongside sales, and for showing attainment against a target that moves with the market.

2 · The framework PROPOSAL

Porsche's announcement of the 2025 Importer of the Year for the Middle East region states what the award looks at: customer satisfaction, service quality, sales innovation, team efficiency and the ability to build long-term loyalty. I used those five as the pillars. The KPIs under them are my proposal, not Porsche's list.

The posting asks for partners to be evaluated on financial, integrity, data and business-stability risk with material issues escalated. Gates keep that separate from performance so a strong sales year cannot offset a compliance problem, and the reason for an exclusion is always stated.

3 · The scoring method

Every step is simple enough to explain to an importer's general manager in one minute, which is the test for a methodology that gets published.

  1. Clean first. Data-quality rules run before scoring (section 6). Bad values are excluded and replaced with the importer's own mean of its other quarters, and each one is logged.
  2. Attainment per KPI = actual ÷ target where higher is better, target ÷ actual where lower is better, capped at 110% so one outlier KPI cannot carry a pillar.
  3. Pillar score = weighted mean of its KPI attainments × 100. 100 means every target was met.
  4. Total = pillar scores × pillar weights (30 / 20 / 20 / 15 / 15).
  5. Eligibility: any red gate removes the importer from the award ranking. The score is still shown.

Choices I would put in front of the importers

  • Targets, not peer rank, inside the score. An importer is measured against a fixed target, so one importer improving does not push another down.
  • A cap at 110% rewards beating a target without letting one KPI dominate.
  • Weights are policy, not maths. That is why section 5 tests how much they matter.
  • Four quarters averaged to reduce the effect of one bad quarter. A rolling view is a better fit for in-year steering.

    6 · Data quality runs before scoring SYNTHETIC DATA

    Four rules run on every submission. In this prototype I injected four deliberate errors into the synthetic data to confirm the rules find them. That shows the rules work on those four patterns, nothing more: real submissions will contain errors I have not thought of.

    R1 CompletenessNo blank values for a KPI an importer must report

    R3 Impossible zeroA rate such as pre-owned sales or conversion that reads exactly 0

    Core measures (DAX)

    KPI Attainment =
VAR Actual = AVERAGE ( fact_kpi_quarterly[value_used] )
VAR Target = SELECTEDVALUE ( dim_kpi[target] )
VAR HigherBetter =
    SELECTEDVALUE ( dim_kpi[direction] ) = "higher is better"
RETURN
    MIN ( 1.1,
        IF ( HigherBetter,
            DIVIDE ( Actual, Target ),
            DIVIDE ( Target, Actual ) ) )

Pillar Score =
SUMX (
    VALUES ( dim_kpi[kpi_id] ),
    [KPI Attainment]
        * CALCULATE ( MAX ( dim_kpi[weight_in_pillar] ) )
) * 100

Total Score =
SUMX (
    VALUES ( dim_pillar[pillar_id] ),
    [Pillar Score]
        * CALCULATE ( MAX ( dim_pillar[base_weight] ) )
)

Eligible =
IF ( SELECTEDVALUE ( fact_risk_gates[gate_status] ) <> "RED", 1, 0 )

    Migration plan I would run

    1. Inventory and freeze definitions. List every report and KPI in use today, who owns it, which source feeds it. One written definition per KPI, signed off before anything is rebuilt.
    2. Build the model once. Star schema, one measure layer, no logic in report pages.
    3. Run old and new in parallel for one reporting cycle and reconcile every difference to a cause, so users trust the new numbers.
    4. Row-level security so each importer sees only its own data and the peer ranking.
    5. Monitoring: data-quality log published with every refresh, refresh failures alerted, a named owner per table.
    6. Retire the old reports on a stated date, not gradually.

    9 · Limits, stated plainly

    • Importer data is synthetic. Generated with a fixed random seed (20261115). Real importer KPIs are internal to the manufacturer, and I chose not to scrape or guess at partners' public data. Which importer ranks first here tells you nothing about any real importer.
    • The KPI list, targets, weights and gate thresholds are my proposals. They mirror the five published criteria but are not Porsche's definitions.
    • The weight-sensitivity result depends on the synthetic spread. The method transfers; the finding does not.
    • Derived delivery years are approximate and marked as such.
    • The Power BI report is a prototype page (scorecard table, ranked bars by risk gate, pillar heatmap). Pillar weights are fixed in dim_pillar; a live what-if weight slider is not built.
